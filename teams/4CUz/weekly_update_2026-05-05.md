# **Weekly Update — May 5**

## **What we built last week and why**

Last week, we focused on polish, reliability, and making the main trip experience smoother. We improved availability by showing members and hover states, added itinerary date-range constraints, updated the logo, and refined delete functionality and account/session behavior. We also worked on background image selection and list reordering. These changes were deliberate because the MVP already had the core planning pieces, so the next step was making those pieces feel usable and understandable.

The biggest reason for this work was to reduce confusion inside the trip dashboard. If users can see who is available, reorder trip information, and manage their trips more cleanly, they are more likely to understand Tripable as a shared planning workspace rather than a static document. GitHub shows commits for availability members, availability hover, itinerary constraints, logo updates, delete functionality, password reset, and background image selection during this stretch.

## **What we’re building this week and why**

This week, we are doing final UI cleanup, fixing edge cases, and preparing the product for demo and user testing. We are also checking the expenses flow because cost-splitting is one of the features users expect when planning a group trip.
