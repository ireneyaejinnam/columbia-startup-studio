**Week of April 9, 2026**

## What We Built Last Week and Why

We shipped the full core app. This was our foundational sprint — everything needed for a user to go from zero to finding an event they care about:

- **React Native app with Expo Router** — file-based navigation across auth, onboarding, discovery, plan, and profile tabs. We chose Expo because it lets us iterate quickly and deploy OTA without App Store resubmissions for JS-layer changes.
- **4-step onboarding wizard** — collects interests, available days/times, borough, and budget. Without this, every new user gets a cold generic feed. The wizard seeds the recommendation engine before a single swipe happens.
- **Guest mode** — users can browse events without signing in, with saves persisting after sign-up. We added this because forcing sign-up before showing value is the fastest way to lose users.
- **Recommendation engine** — scores events by category match, location, budget, and schedule against the user's onboarding profile. This is the core product differentiation.
- **Event detail screen** — full event info with ticket links and calendar export (Google + Apple).
- **Plan tab** — shortlist saved events, confirm a plan, export to calendar.
- **Daily event ingestion pipeline** — Vercel cron pulling from 14 sources (Ticketmaster, Eventbrite, NYC Parks, museums, Dice, Resident Advisor, and more). Without live data the app is a demo, not a product.
- **Supabase** for auth and database, with RLS policies on all user tables.
- **Amplitude + Firebase Analytics** — full funnel tracking from `onboarding_started` through `sign_up_completed`.
- **`/api/user-count` and `/api/metrics` endpoints** — public endpoints for the class leaderboard.

## What We're Building This Week and Why

- **Taste profile that learns from swipes** — the onboarding profile is a one-time snapshot. We want the feed to get smarter the more you use it, updating category and tag weights on every like, dislike, and save. This closes the loop between user behavior and recommendations.
- **AI event discovery pipeline** — a second ingestion pipeline using Claude to discover events via web search that scrapers miss. We want broader, less mainstream coverage.
- **Hook text generation** — short one-line descriptions for each event card ("think: Jazz in a basement wine bar") generated by GPT-4o-mini. Events without good copy don't get clicked.
